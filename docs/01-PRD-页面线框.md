# PUBG 复盘分析台 — 页面线框级 PRD

> 版本：v0.1  
> 定位：复盘分析台（查询是入口，分析与改进建议是价值）  
> 文档顺序：待办见 `00-待办清单.md`；本文为 PRD；接口设计见 `02-API与表结构设计.md`

---

## 1. 产品概述

### 1.1 一句话目标

输入玩家昵称 → 看懂最近怎么赢/怎么输 → 得到可执行改进建议。

### 1.2 目标用户

| 用户类型 | 诉求 | 核心路径 |
|----------|------|----------|
| 普通玩家 | 查战绩、看自己弱在哪 | 搜索 → 概览 → 对局复盘 |
| 进阶玩家 | 细抠对局、武器/地图偏好 | 对局详情 → 2D 回放 → 分析页 |
| 小队玩家 | 对比队友、找配合问题 | 收藏好友 → 对比（P2） |

### 1.3 成功指标

| 指标 | 目标 |
|------|------|
| 搜索到概览首屏（缓存命中） | < 2s |
| 对局详情打开（已入库） | < 1s |
| 每场复盘报告含可解释主因标签 | ≥ 1 个 |
| 搜索用户中打开至少 1 场详情 | ≥ 40% |
| 7 日回访（收藏玩家驱动） | 持续观察 |

### 1.4 范围边界

**做**

- 多平台玩家查询、赛季/生涯概览、近期对局、对局详情
- 规则引擎复盘报告、弱点标签
- Telemetry 事件轴与 2D 回放（分阶段）
- 收藏玩家、历史入库（突破官方 14 天列表限制）

**不做（本期）**

- 账号登录强绑定游戏（可先本地/简易账号）
- 实时直播叠层、代练验证
- 全服排行榜爬取、非 opt-in 全量采集
- 移动端原生 App（Web 响应式即可）

## 3. 全局交互规范

### 3.1 平台与搜索

- 平台枚举：`steam` | `kakao` | `xbox` | `psn`
- 默认平台：`steam`（可记忆上次选择）
- 昵称提示：严格大小写；失败时提示「请与游戏内显示完全一致」
- 支持历史搜索下拉（本地 recent 10 条）

### 3.2 状态与反馈

| 状态 | 表现 |
|------|------|
| Loading | 骨架屏（KPI 卡、表格行） |
| 空数据 | 插画 + 文案 + 重试/换平台 |
| API 限流 | 「查询拥挤，请稍后」+ 倒计时重试 |
| 玩家不存在 | 「未找到玩家，请检查平台与大小写」 |
| 对局过期 | 「官方仅保留约 14 天；若已收藏会尽量保留已同步数据」 |

### 3.3 视觉基调

- 深色电竞风，大数字 KPI
- 模式色：Solo / Duo / Squad、FPP / TPP 用标签区分
- 排名高亮：#1 金色，Top10 绿色，其余中性

## 5. 关键用户流程

### 5.1 主路径：查询并复盘

```
首页输入昵称
  → 玩家概览（看 KPI + 弱点标签）
  → 点最近一场
  → 复盘报告（读结论与建议）
  → （可选）事件轴 / 2D 回放验证
  → 返回分析 Tab 看聚合问题
```

### 5.2 收藏增长路径

```
概览点收藏
  → 之后自动同步新对局
  → 分析 Tab 数据越来越完整
  → 7 日回访查看新报告
```

## 8. 文案与空态清单（摘录）

| 场景 | 文案 |
|------|------|
| 玩家不存在 | 未找到该玩家。请确认平台，并保证昵称与游戏内大小写一致。 |
| 暂无对局 | 近 14 天暂无对局记录。收藏该玩家后，有新对局将自动同步。 |
| 报告生成中 | 正在生成本场复盘报告，通常几秒内完成… |
| 回放不可用 | 本场遥测数据已过期或解析失败，仍可查看积分板与基础复盘。 |
| 触发限流 | 当前查询较多，请 XX 秒后重试。 |
