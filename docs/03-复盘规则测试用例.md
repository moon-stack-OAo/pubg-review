# 复盘规则测试用例

> 版本：`1.0.0-no-telemetry`（降级） / `1.1.0-telemetry`（增强）  
> 引擎：`report-engine.ts`、`report-engine-telemetry.ts`  
> 说明：无遥测用例仅用 match + participant；增强用例叠加死亡时刻 telemetry 特征。

---

## 约定

| 符号 | 含义 |
|------|------|
| `duration` | 对局总时长（秒） |
| `t` | `survivalTimeSec` |
| `phase` | early: `t < 0.25*duration`；mid: `< 0.70`；late: 其余 |
| 主因 | 优先高置信负向；同级按权重 hot_drop > early_exit > mid_overfight > aim_inconsistent > low_damage；仅正向则为 good_game |

文案须含「基于基础战绩的初判」。

---

## 用例 1：热点落地（弱化 hot_drop）

**输入特征**

| 字段 | 值 |
|------|-----|
| duration | 1800 |
| survivalTimeSec | 90（early） |
| winPlace | 78 |
| kills | 0 |
| damageDealt | 40 |
| walkDistance | 80 |

**期望**

- 标签含 `hot_drop`（confidence ≈ medium）
- 主因：`hot_drop`
- 不强制要求 `early_exit`（hot_drop 优先于 early 分支）

**边界**

- `walkDistance >= 200` 或 `survivalTimeSec >= 180` 时应变为 `early_exit`，而非 hot_drop。

## 用例 6：优质对局（good_game）

**输入特征 A（吃鸡）**

| 字段 | 值 |
|------|-----|
| duration | 1800 |
| survivalTimeSec | 1700 |
| winPlace | 1 |
| kills | 5 |
| damageDealt | 600 |

**输入特征 B（高排高伤）**

| 字段 | 值 |
|------|-----|
| winPlace | 2 |
| damageDealt | 550 |
| （其余合理 mid/late） | |

**期望**

- 标签含 `good_game`（high）
- 若同时存在负向标签，主因仍优先负向；仅 `good_game` 时主因可为正向
- suggestions 可含巩固优势类正向建议

## 用例 8：中期第三人（遥测增强 mid_third_party）

**前置**：本地 `telemetry.status=ready`，`events.json` 可用。

**输入特征（participant）**

| 字段 | 值 |
|------|-----|
| duration | 1800 |
| survivalTimeSec | 900（mid） |
| winPlace | 22 |
| kills | 2 |
| damageDealt | 380 |

**遥测特征（死亡窗口 ~20s）**

| 特征 | 值 |
|------|-----|
| deathT | ≈900 |
| enemiesNearbyAtDeath | ≥3（80m 内） |
| attackerCountInWindow | ≥2（kill/knock 攻击者去重） |

**期望**

- `ruleVersion` = `1.1.0-telemetry`
- `degraded` = false
- 标签含 `mid_third_party`（high）；通常不再保留同场 `mid_overfight` 作为主因竞争项
- summary 含「已结合遥测」与附近敌人/攻击者计数
- 无遥测时同 participant 仅可能出 `mid_overfight`（low），不得出 `mid_third_party`

---

## 用例 9：收边偏晚 + 脱离队伍（late_rotate / isolated_death）

**前置**：telemetry ready；`gameMode` 含 squad/duo。

**输入特征（participant）**

| 字段 | 值 |
|------|-----|
| duration | 1800 |
| survivalTimeSec | 1300（late） |
| winPlace | 12 |
| kills | 2 |
| damageDealt | 320 |
| rideDistance | 200 |

**遥测特征**

| 特征 | 值 |
|------|-----|
| death 点相对 safetyZone | 圈外或距边 &lt;100m（区外为正） |
| teammateDistanceAtDeath | ≥150m |

**期望**

- 标签含 `late_rotate`（圈外 high / 贴边 medium）与 `isolated_death`（medium）
- suggestions 含收边与跟队相关中文建议
- summary 提及圈距与最近队友距离
- `endgame_nades`：仅当近战/近距离武器致死且无投掷痕迹时可出 low；否则可跳过

## 手动抽检清单

1. 打开已缓存对局详情页，确认报告卡在个人数据上方。  
2. `GET /api/v1/matches/{matchId}/report?platform=&accountId=` 返回上述字段。  
3. `POST .../report/rebuild` 后 `generatedAt` 更新且 meta.rebuilt=true。  
4. 玩家页近期对局「标签」列显示主因中文；失败显示 `-`。  
5. 先出降级报告 → `POST .../telemetry/parse` 至 ready → 刷新或 rebuild → `ruleVersion` 变为 `1.1.0-telemetry`，文案为「已结合遥测」。  
6. 报告卡展示 ruleVersion 与「遥测增强 / 降级初判」区分。
