## 1. 决策摘要

| 议题      | 结论                                                    |
|---------|-------------------------------------------------------|
| AI 分析   | **可选外挂 LLM 增强**：规则引擎仍是事实源；有 Key 时润色摘要/建议；无 Key 时与现网一致 |
| 地图底图    | **可使用官方 api-assets 地图**（非「技术不能」；此前暂缓是版权/体积/工程取舍）      |
| 载具 / 船  | 补遥测解析 + 回放图层                                          |
| 密室 / 建筑 | **仅做 POI / 建筑轮廓近似**，不承诺游戏内逐房间还原                       |

### 1.1 官方地图可用性

- 资源库：[pubg/api-assets](https://github.com/pubg/api-assets) → `Assets/Maps/`（各图 High/Low Res、有字/无字 PNG）
- 须遵守：[Developer ToS](https://developer.pubg.com/tos)、Player-created Content，以及仓库内使用说明；**页脚/关于处署名**
- 体积：High_Res 单图常约 80–100MB（Git LFS）；产品默认优先 **Low_Res / No_Text**，跟随缩放再考虑高清
- 与遥测：`mapName`（如 `Baltic_Main`）经 dictionary / 本站 `maps.ts` 映射到资源文件

### 1.2 现状一句话

| 域                | 现状                                                                     |
|------------------|------------------------------------------------------------------------|
| 分析               | 确定性规则 + 模板文案（`1.0.0-no-telemetry` / `1.1.0-telemetry`）；**无 LLM 依赖与调用** |
| 回放               | 纯色画布 + 轨迹 / 圈 / 枪线 / `?t=`；自标 MVP                                      |
| 载具 / 船 / 建筑 / 房间 | **Telemetry 与 UI 均未建模**；仅有 participant `rideDistance` 等弱启发             |
| MCP              | 13 Tools 暴露报告/分析/form；**无** parse / events 流 Tool                      |

## 2. 缺口清单

图例：`[ ]` 未开始 · `[~]` 进行中 · `[x]` 已完成 · `[-]` 暂缓

### A. 官方地图底图（优先）

独立地图中心已提供地图目录与资料页；地图战绩统计、对局地图复盘暂留后续迭代。

```text
[x] A1  mapName → api-assets 文件名映射（含 No_Text / Low_Res 优选）
[x] A2  静态资源策略：public/maps/ 或构建拉取；避免默认打进巨型 High_Res
[ ] A3  坐标对齐抽检（Erangel / Sanhok 等 1～2 图 + mapSizeCm）
[ ] A4  回放文案改为「官方 api-assets + 署名」，去掉「非官方贴图」误导
[x] A5  页脚 / 关于：PUBG / api-assets 署名与 ToS 链接
```

**依赖 / 风险**：ToS 合规、部署体积、未知新图缺尺寸时回退默认边长。

### B. 地图图层：载具 / 船 / 空投 / 死亡点

```text
[ ] B1  解析 LogVehicle*（上车 / 下车 / 摧毁 / 骑乘等）→ vehicles[] + 事件类型扩展
[ ] B2  船 vs 车：api-assets dictionaries/telemetry/vehicle 映射展示名与图标
[ ] B3  回放图层：载具轨迹、当前载具点、船上标记；开关可关
[ ] B4  空投点绘制（已有 carePackage 事件，画布未画）
[ ] B5  死亡 / 倒地固定标记（可与 ?t= / 事件轴联动）
[ ] B6  队伍列表面板（选人 / 跟队；对齐 PRD 侧栏）
```

**破坏性**：`parserVersion` 升至 `1.2.0`（或约定次版本）；旧 `events.json` 需重 parse。

### C. 建筑 / 「密室」近似（预期管理）

```text
[ ] C1  文档与 UI 明确：官方遥测无稳定「房间 ID」，不做逐房间还原
[ ] C2  自维护 POI 点 / 建筑多边形（优先常用图常用点）
[ ] C3  用 position + POI 命中做「疑似室内 / 院落」标记（可选 z 辅助）
[-] C4  完整 3D 建筑 mesh / 门窗级碰撞 — 暂缓
```

### D. AI 分析（可选外挂 LLM）

```text
[ ] D1  规则引擎底稿不变：primaryTag / metrics / confidence 仍是事实源
[ ] D2  环境变量：AI_ANALYSIS_ENABLED + 模型网关 Key；默认关闭
[ ] D3  增强点：① 单场人话复盘 ② 玩家分析建议润色 ③ 可选短上下文追问本场
[ ] D4  只送脱敏结构化 JSON（无 API Key、无 CDN URL、无 raw telemetry）
[ ] D5  服务端调用 + 限流 + 缓存（matchId + ruleVersion + promptVer）
[ ] D6  UI：「AI 解读」区块；失败降级回规则文案；标注「AI 辅助，非官方判定」
[ ] D7  （可选）MCP `explain_match_report`；或继续由外部 Agent 读现有 report
```

**依赖 / 风险**：密钥仅服务端；单实例下勿与 telemetry 重 parse 抢满官方 RPM；弱样本仍须降级展示。

### E. 分析规则补强（不依赖 LLM）

```text
[ ] E1  vehicle_risk：载具中阵亡 / 载具炸毁（依赖 B1）
[ ] E2  落地 / POI 热点聚类（依赖 C2）
[ ] E3  空投相关标签（carePackage + B4）
[ ] E4  MCP：parse_telemetry / get_telemetry_events（外部 Agent 验回放）
```

### F. 工程与合规

```text
[ ] F1  地图资源 LICENSE / 署名检查清单（上线前勾选）
[ ] F2  parserVersion 与报告 ruleVersion 升级说明写入 CHANGELOG / docs/04
[ ] F3  回放性能：点过多抽稀、图层默认策略、大图懒加载
[ ] F4  AI 与重 parse 串行 / 冷却，禁止定时全量扫库 Job
```

## 4. 明确不做 / 暂缓（本专题）

```text
[-] 官方地图贴图「破解 / 私服 Extraktion」来源（只用 api-assets 或自建示意）
[-] 逐房间密室 / 完整建筑碰撞
[-] 本站强制绑定某一闭源大模型（网关可配置；默认关）
[-] 用 AI「判定开挂」（banType 仍只表示官方封禁）
[-] Redis / 多实例仅为撑 AI 或贴图 CDN（无多实例需求前）
```

---

## 5. 改动前自检（继承 AGENTS）

1. 是否额外打满官方 ~10 RPM？贴图与 LLM 是否走本地/缓存？
2. 前端是否仍只打 BFF？
3. 无 telemetry / 弱样本 / 无 AI Key 时是否降级而非假数据？
4. 单实例与 `.data` 语义是否被破坏？
5. 地图与 AI 文案是否客观、有署名、无侮辱、不开挂暗示？
